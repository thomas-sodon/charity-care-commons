Methods

How a hospital's financial-assistance policy becomes the rules on this site. The model extracts; code computes; people verify.

1. Find the hospitals and their filings

We start from the CMS list of Texas hospitals and each nonprofit's IRS Form 990 Schedule H (Part V), which reports the free-care and discount cutoffs, whether an asset test, insurance status or residency is used, and the web addresses of the policy, application and plain-language summary.

2. Fetch and hash every document

Each PDF is stored with its sha256 hash, the date we fetched it, and a Wayback copy where one exists. The hash is the document's identity: if a single byte changes, it is a new version and goes through review again.

3. Compile the policy, with quotes

A language model reads the policy and returns 23 structured fields (income tiers, asset test, residency, documents, deadlines and more). Every value must come with a verbatim quote and page number. Our own verifier then looks for each quote on the cited page of the hashed document. No quote, no publish. Values whose quote cannot be found are dropped and sent to a reviewer.

5. Check against the IRS filing

Only unexplained disagreements can be listed as discrepancies for review, and only after a reviewer has verified the policy value and the hospital has had a right of reply: an item is shown once the hospital's response is published or 10 business days after the reviewer's confirmation started the reply window. Replies appear next to the item. Disagreements on superseded policy versions are withdrawn. A notice record is kept for each item; sending it to the hospital is a maintainer step outside this software.

6. Human review

Every field starts as ○ provisional. A reviewer looks at the source page next to the extracted value and the IRS value, then approves, corrects, abstains or asks the hospital. Only ✓ verified fields are used when screening a household; a screening that would rely on provisional fields is labelled preliminary.

7. Screening is plain code

Household income is divided by the HHS poverty guideline for the household size and year the policy specifies, and compared with the verified tiers using exact arithmetic. Results are worded as “likely eligible” estimates with the policy quote and the arithmetic shown, never as a decision. The hospital decides.

8. Privacy

We never store household facts, bills or pay stubs. Screening requests are processed in memory and are not logged; logs keep only the route, status and timing.

9. Freshness and sunset policy

Every page and API response carries the date the data was last verified. If nothing has been re-verified for {{ stale_after }} days (for example, if maintenance stops), the site shows a warning and the API returns stale: true.
